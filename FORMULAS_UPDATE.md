# Обновление математической модели по статье

Проект приведён к формулам из статьи «Моделирование нестационарных режимов работы информационно-измерительной системы медицинского назначения».

## Реализованные зависимости

Для MAP/M/1/N-модели используются следующие характеристики:

- `N_b(t) = sum_{k=1}^N k * sum_i P(k+1,i,t)` — среднее число заявок в буфере, формула (12);
- `P_fail(t) = sum_i P(N+1,i,t)` — вероятность отказа, формула (13);
- `v_loss(t) = nu * N_b(t)` — интенсивность ухода нетерпеливых заявок, формула (14);
- `lambda(t) = sum_k p_k(t) * D1 * e` — нестационарная интенсивность входного MAP-потока, формула (15);
- `P_uns(t) = integral(v_loss) / (E[N(t0)] + integral(lambda))` — вероятность ухода в переходном режиме, формула (16);
- `P_loss(t) = P_fail(t) + P_uns(t)` — вероятность потерь, формула (20);
- `P_serv(t) = 1 - P_loss(t)` — вероятность обслуживания, формула (21);
- `A(t) = P_serv(t) * lambda(t)` — пропускная способность, формула (22).

Интегралы вычисляются накопленным методом трапеций по заданной временной сетке. Если сетка начинается с `t0 != 0`, расчёт ведётся от первой точки сетки.

## Исправления решателя

- аналитическое решение теперь использует столбцовую запись `P(t) = L(t) @ P(t0)`;
- экспоненты строятся по времени `t - t0`, поэтому `P(t0)` точно совпадает с начальным распределением;
- NumPy-решатель допускает комплексно-сопряжённые собственные значения матрицы `Q`, которые штатно возникают у MAP-генераторов;
- версия математической реализации включена в ключ DuckDB-кэша, поэтому старые закэшированные матрицы не подменяют новые результаты;
- спектральная диагностика численного метода теперь вычисляет `alpha_min = min |Re(gamma_i)|` и `tau_max = 1/alpha_min`, как в разделе о времени переходного режима.

## Проверка на численном примере статьи

Для параметров статьи `M=4`, `N=15`, `mu=500`, `nu=300`, `lambda=[167, 692, 1250, 4833]` и матриц вероятностей из формул (23)-(24) проверено:

- размер генератора `Q`: `68 x 68`;
- суммы элементов каждого столбца `Q` равны нулю с машинной точностью;
- `lambda_bar = 464.189992` пакетов/с, что соответствует приведённому в статье значению `464.2`;
- `alpha_min = 369.590955`;
- `tau_max = 0.00270569` с;
- аналитическое и численное решения на интервале `[0; 0.04]` совпадают с максимальным расхождением порядка `4e-6`.

## Важное замечание о таблице 1 статьи

Текст формулы (14) содержит множитель `k`, то есть поток ухода равен `nu * N_b(t)`. При прямой подстановке эта формула даёт другие стационарные значения `P_uns`, `P_loss` и `A`, чем часть чисел, приведённых далее в таблице 1 и на рисунках статьи. Прежняя версия проекта фактически использовала невзвешенную вероятность непустого буфера и потому была ближе к этим табличным значениям.

В данной редакции приоритет отдан **формально записанным формулам (12)-(22)**, как и требовалось при обновлении проекта. Поэтому повторный расчёт старых сценариев может дать заметно отличающиеся значения вероятности ухода, вероятности потерь и пропускной способности.
